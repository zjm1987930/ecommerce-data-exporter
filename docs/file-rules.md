# 文件与目录规则

## 根目录

建议所有平台导出的原始数据保存到统一根目录：

```text
原始数据/
```

如果后续需要和现有报表工具对接，可以将该根目录配置为报表工具的输入目录。

已确认第一版输出根目录放在项目根目录下：

```text
D:\数据自动导出工具\原始数据\
```

## 数据类型和日期范围目录

每次运行默认导出上一个自然月的数据。用户也可以手动选择日期范围。为避免同月多次导出难以区分，目录和文件名统一使用实际选择的日期范围。

目录格式：

```text
数据类型/YYYYMMDD-YYYYMMDD/店铺/
```

示例：

```text
原始数据/
  退货数据/
    20260501-20260515/
      拼多多大雁书籍专营店/
        20260501-20260515拼多多大雁书籍退货.xlsx
  延迟发货数据/
    20260501-20260515/
      拼多多大雁书籍专营店/
        20260501-20260515拼多多大雁书籍延迟发货.xlsx
        延迟发货_平台原始文件/
```

## 文件命名规则

用户已有报表工具对文件命名有固定要求。具体命名格式待用户提供后补充。

在用户提供正式命名规则前，项目内部建议临时使用以下格式：

```text
数据类型.扩展名
```

示例：

```text
退货数据.xlsx
消费者负向体验扣款数据.xlsx
延迟发货数据.xlsx
```

如果一个数据类型一次导出多个文件，建议临时使用序号：

```text
退货数据_1.xlsx
退货数据_2.xlsx
```

后续确定现有报表工具要求后，以现有报表工具要求为准。

已确认的拼多多命名规则：

- 所有最终输出文件名都以实际选择的日期范围开头，格式为 `YYYYMMDD-YYYYMMDD`。
- 退货数据保存为 `YYYYMMDD-YYYYMMDD + 店铺短名 + 退货.xlsx`。
- 客服绩效数据保存为 `YYYYMMDD-YYYYMMDD + 店铺短名 + 客服绩效.xls`。
- 延迟发货数据整合后的文件保存为 `YYYYMMDD-YYYYMMDD + 店铺短名 + 延迟发货.xlsx`。
- 消费者负向体验扣款数据保存为 `YYYYMMDD-YYYYMMDD拼多多负向体验.xlsx`，仍按店铺分 sheet。
- 延迟发货数据平台下载文件格式为 XLSX；平台默认文件名待开发时实际下载确认。
- 延迟发货数据最终需要把 3 个 TAB 的 XLSX 整合成一个工作簿。
- 延迟发货数据平台原始下载的 3 个 XLSX 需要保留，方便核对。

## 特殊文件规则

### 延迟发货数据

拼多多延迟发货数据包含 3 个 TAB：

- 延迟发货
- 缺货
- 虚假发货/虚假轨迹

工具需要将 3 个 TAB 分别导出的文件整合到一个工作簿中。

整合后工作簿的 sheet 顺序必须为：

1. 延迟发货
2. 缺货
3. 虚假发货/虚假轨迹

如果某个 TAB 无数据，也要保留该 sheet，并写入该 TAB 的表头。

3 个 TAB 的平台导出字段不完全一致，整合时各 sheet 保留各自原始表头，不做字段对齐或合并。

原始下载文件放入店铺目录下的子目录：

```text
延迟发货_平台原始文件/
```

### 消费者负向体验扣款数据

消费者负向体验扣款数据没有导出按钮，需要采集网页表格。

采集后的保存格式必须尽量保持用户当前手动复制粘贴的格式，以便兼容已有报表汇总工具。

示例文件：

```text
示例/4月拼多多负向体验4.1-4.30.xlsx
```

示例是一个工作簿，按店铺分 sheet。后续工具生成的消费者负向体验扣款数据也应使用同样结构。

sheet 名必须与示例一致：

1. 拼多多金喆
2. 拼多多逸观
3. 拼多多大雁
4. 拼多多大雁母婴玩具
5. 拼多多大雁母婴
6. 拼多多大雁书籍
7. 拼多多大雁童书
8. 拼多多逸观母婴玩具
9. 拼多多逸观书籍

表头必须与示例一致：

| 列序号 | 字段名 |
| ---: | --- |
| 1 | 订单编号 |
| 2 | 商品信息 |
| 3 | 问题类型 |
| 4 | 补偿金额（元） |
| 5 | 扣款进度 |
| 6 | 创建时间 |
| 7 | 处理状态 |
| 8 | 操作 |

示例保留网页复制后的多行结构，单条记录可能占用多行。后续工具应尽量复刻该结构，不要擅自压平成一行一条记录。

当用户选择超过 7 天的日期范围时，工具应拆分采集，但最终同一店铺的数据仍合并到同一个店铺 sheet 中。

如果某个店铺无数据，也要保留对应店铺 sheet，并写入表头。

文件命名参考示例：

```text
20260501-20260515拼多多负向体验.xlsx
```

单店或部分店铺补跑时，如果同日期范围工作簿已经存在，只替换本次参与店铺的 sheet，其余店铺 sheet 保留，避免覆盖前面已成功店铺。

## 日志文件

每次运行必须生成导出日志。

建议日志位置：

```text
原始数据/
  导出日志/
    YYYYMMDD-YYYYMMDD/
      导出日志_时间.csv
```

也可以同时生成机器可读日志：

```text
原始数据/
  导出日志/
    YYYYMMDD-YYYYMMDD/
      export-log_时间.json
```

## 日志字段

导出日志至少包含：

| 字段 | 说明 |
| --- | --- |
| 月份 | 数据所属月份，例如 2026-04 |
| 平台 | 例如 拼多多 |
| 店铺 | 店铺名称 |
| 数据类型 | 例如 退货数据 |
| 开始日期 | 本次任务查询开始日期 |
| 结束日期 | 本次任务查询结束日期 |
| 子任务序号 | 日期被拆分时记录分段序号 |
| 状态 | 成功、无数据、失败、跳过 |
| 文件路径 | 成功导出后的文件路径 |
| 失败原因 | 失败时记录 |
| 开始时间 | 任务开始时间 |
| 结束时间 | 任务结束时间 |
| 截图路径 | 出错或关键步骤截图 |

## 状态定义

状态建议统一为：

- 成功：已导出文件并完成归档。
- 无数据：已查询，但当月没有可导出数据。
- 失败：任务执行出错，需要人工检查。
- 跳过：因配置或前置条件未满足而跳过。
- 未选择：用户本次没有选择该数据类型。
- 部分成功：日期拆分后部分子任务成功，部分子任务失败。

## 覆盖规则

默认不直接覆盖已有文件。

如果目标文件已存在，建议先备份旧文件或生成带时间戳的新文件，避免误删历史数据。

建议策略：

```text
退货数据.xlsx
退货数据_重复_20260525_114500.xlsx
```

后续可增加“允许覆盖”配置，但默认应保持谨慎。
